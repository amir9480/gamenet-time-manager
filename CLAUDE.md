# Gamenet Timer Manager (نرم افزار مدیریت زمان گیم نت)

Single-page Persian (RTL, Vazirmatn) game-net session/cost tracker. React + Vite + TypeScript + Tailwind v4 + shadcn/ui (Base UI based "base-nova" style), wrapped as a Tauri v2 desktop app. Data (price types, extra items, sessions, history) lives in IndexedDB via Dexie; only theme/accent live in `localStorage`.

## Commands (pnpm only)
- `pnpm dev` — Vite on `0.0.0.0:3000` (strictPort; Tauri `devUrl` points at `localhost:3000`).
- `pnpm build` — `tsc -b && vite build` (strict, `noUnusedLocals`); run after every change.
- `pnpm tauri dev` — desktop window. `pnpm tauri build --no-bundle` — portable exe in `src-tauri/target/release/` (named after the Tauri `productName`) (no installer; window starts maximized).
- Add shadcn components with `pnpm dlx shadcn@latest add <name> -y`.

## Product model
- **Rates** (نرخ‌ها): named rate groups, each with several per-hour prices + a default (`RateGroup`/`Price`). **Devices**: categories (default پی‌سی، پلی‌استیشن، بیلیارد، پینگ‌پنگ) → devices created in bulk (prefix + count + start number); each device links to ≥1 rate groups and offers all their prices (grouped in selects). A **session** runs on one free device: Add-session picks category → free device → price (default = first group's default) → optional **customer**. The card's price select ends with «تغییر دستگاه…» (`switchDevice`: closes the segment, opens one on the new device/price; paused sessions apply it on resume). Ending (اتمام) shows a cost breakdown dialog and, once confirmed, writes history and **removes** the session. There is no free-text session name anymore.
- Settings dialog is draft-based (ذخیره/انصراف, close = cancel, discard-confirm when dirty, save disabled while a name is empty / a price is 0 / a device has no rate). Tabs: عمومی (dark mode, accent, autostart), نرخ‌ها (`RateGroupsEditor`), دستگاه‌ها (`DevicesEditor`), بوفه (`ExtraItemsEditor`: extra categories + items; the picker shows category filter chips only when >1 category). داده‌ها (`DataTab`, acts immediately, not part of the draft): export a JSON backup of every table + `gamenet-*` localStorage prefs (`exportBackup`), import it replacing everything (`parseBackup`/`importBackup`, confirm, then reload), clear history only, or factory reset (`resetAllData` = `db.delete()` + prefs, type «حذف» to confirm, then reload). Customers are NOT in Settings: a separate `CustomersDialog` (top-bar Users button; search + 8/page, edit/delete save immediately, soft delete via `deleteCustomer`; `NewCustomerDialog` creates/edits, also inline from the session flow). `saveSettings` ignores customers. Deleting a price/device/customer used by a running session is blocked (`usageOf`); categories/rate groups must be empty/unused first.
- Cost: a session is a list of **segments** (one continuous run on one device at one price; each carries `typeId` + mirrored price name/value and `deviceId/deviceName/categoryName`). Saving Settings rewrites these mirrors for ALL live sessions via `applyPrices`/`applyDevices`/`applyExtraItems` (in one transaction, `saveSettings`); history snapshots are never touched. Changing the price while running closes the segment and opens a new one. Time cost is billed per whole second, rounded up (`segmentCost`). Extra time entries (custom name + minutes + a price from the device's groups; snapshot) are billed at that entry's rate; extra items are `price × qty` (catalog items keep `catalogId`; the «موارد دیگر» item has a raw price and optional description). Total = Σ segments + extra times + extra items.
- **Naming rule: «بوفه»/"buffet" is a UI-only term.** In source code (identifiers, file names, component names, ids, comments, types, DB) always say *extra cost* / *extra item* (`extraItems`, `ExtraItemPicker`, `SaveExtraItemDialog`, `save-extra-item-dialog.tsx`), never `buffet`. Persian UI strings may say «بوفه».
- Wording: the extra-items catalog (`extraItems`/`extraCategories`, Settings tab, picker, stats) is called **«بوفه»** (never «موارد اضافه»/«هزینه اضافه»); extra *time* stays «زمان اضافه». Wording: a `Session` is called **«تایم»** in the UI (never «نشست», which means "sitting"): «افزودن تایم», «تایم‌های پایان‌یافته», «پایان تایم». Wording: a `DeviceCategory` is called **«نوع دستگاه»** in the UI (never «دسته‌بندی»; that word is only for extra-cost categories). New types/categories start with an empty name and a placeholder (e.g. «مثلاً پلی‌استیشن»); an empty name keeps Settings unsaveable. Devices are added with two buttons («افزودن دستگاه» single, «افزودن چند دستگاه» bulk), edited via the pencil dialog, and «نرخ همه» sets the rate groups of every device of a type.
- **نسیه (debt)**: ending a session with a customer offers «پرداخت شد» / «نسیه» in `SessionSummaryDialog`; نسیه sets `HistoryEntry.onAccount` (stats still sum `total` as income; the history dialog has a «نحوه‌ی پرداخت» filter to switch between paid / نسیه / both). A customer's balance = Σ on-account `total` − Σ `payments` rows (Dexie v3 table `payments`, `addPayment`); computed by `readDebts` (all customers, deferred) / `readCustomerLedger`. `CustomersDialog` shows a debt column, «بدهکاران» filter and `CustomerDebtsDialog` (ledger + «ثبت پرداخت», amount ≤ balance); a customer with unpaid debt cannot be deleted. Deleting a history entry removes its debt.
- **Time limit** (محدودیت زمانی): optional `Session.limitMs` = total running-time budget; countdown = `limitMs − elapsedMs` (pause freezes it, extra times don't count). The edit dialog (`LimitDialog`) works on the *remaining* minutes (`setLimit` = elapsed + minutes; `extendLimit` extends from now when already exceeded; `clearLimit` behind a confirm). `LimitAlarmDialog` (mounted once in `App.tsx`) shows one non-dismissable queued dialog for running sessions past their limit (+5 دقیقه / ویرایش / توقف) and beeps via `src/lib/alarm.ts` immediately and every 10 s. It is on top via the `raised` prop of `DialogContent`/`AlertDialogContent`/`useDiscardGuard` (z-100); anything opened from the alarm must pass `raised`.
- **App lock** (قفل برنامه): optional 4–8 digit PIN set in Settings > امنیت (`SecuritySettings`, acts immediately). `src/lib/security.ts` keeps a PBKDF2-SHA-256 salted hash + auto-lock minutes + wrong-attempt counter/`lockedUntil` (30s/1m/5m/15m after every 3 wrong) + `forgotAt` in its own IndexedDB db `gamenet-security` (never in backups; `resetAllData` clears it; `persist()` requested). While locked (page load, lock button, idle) `App` renders ONLY `LockScreen` (+ the DOM-less `LockedLimitAlarm`); `Main` is not mounted at all, so no app HTML exists until the PIN is verified; `useIdleLock` locks after idle; top-bar Lock button only when a PIN exists. «فراموشی رمز» starts a 24h persisted countdown (PIN entry disabled until «لغو»); after 24h «حذف رمز» removes the PIN only. Client-side deterrent, not tamper-proof. The time-limit beep keeps sounding while locked via `LockedLimitAlarm`.
- **Notice** (پیش از شروع بخوانید): `NoticeDialog` (`src/lib/notice.ts`) is a blocking accept-checkbox dialog shown before onboarding to everyone until `NOTICE_VERSION` is accepted (stored in localStorage `gn-notice`, deliberately NOT `gamenet-` so backups/import don't carry it). To announce an update: bump `NOTICE_VERSION` and add bullets to `NOTICE_UPDATES[version]` (shown as «تغییرات این نسخه» to users who accepted an older version); edit `NOTICE_LIMITS` for the limits list.
- Display: English digits with thousands separators, label «تومان» placed **outside** inputs.

## Code map
- `src/lib/store.ts` — types, defaults (`defaultSettings`), price/device helpers (`devicePriceGroups`, `defaultPriceFor`, `freeDevices`, `selectedPrice`), session transitions (`createSession`, `pauseSession`, `resumeSession`, `changeType`, `switchDevice`), cost helpers, `buildHistoryEntry`, `useLocalStorage`. Business logic belongs here, not in components.
- `src/lib/format.ts` — `formatNumber`, `parseNumber` (accepts Persian/Arabic digits), `formatDuration`, `formatClock`. `src/lib/accents.ts` — generated accent list; `src/accents.css` — generated per-accent CSS vars (`:root[data-accent=…]` / `.dark[data-accent=…]`).
- `src/App.tsx` — reads settings/sessions via `useLiveQuery`, empty state (CTA opens Settings > دستگاه‌ها when no devices), add-session flow. `src/components/session-card.tsx` is the per-session UI. Dialogs: `AddSessionDialog` (step-by-step radio cards: type → device → rate → customer; nothing is preselected and picking a card auto-advances to the next step; steps with a single choice are skipped and auto-filled; busy devices stay visible but disabled with a red dot; a quick-search combobox above the steps jumps ahead), `DevicePicker` (used by `ChangeDeviceDialog`), `ChangeDeviceDialog`, `CustomerPickerDialog`/`CustomerSelect`, `ExtraTimeDialog`, `ExtraItemPicker`, `ExtraItemsManageDialog`, `SessionSummaryDialog`, `SettingsDialog`. **Every dialog with entered data must route X/Esc/overlay/cancel through `useDiscardGuard` (`discard-dialog.tsx`).** `timer.tsx` uses `@number-flow/react`.
- `src-tauri/` — Tauri config (`tauri.conf.json`), autostart plugin (`tauri-plugin-autostart`, permissions in `capabilities/default.json`; the JS side is guarded by `'__TAURI_INTERNALS__' in window`). App icon source: `app-icon.svg` (`pnpm tauri icon app-icon.svg`).

## Conventions & gotchas
- **File names are always kebab-case** (`session-card.tsx`, `use-now.ts`), for new files and renames (use `git mv`; on Windows case-only renames need a temp name). Exports and component names stay PascalCase/camelCase; imports use the `@/components/session-card` form.
- Style: single quotes, no semicolons, ~100 col, trailing commas. Do **not** run prettier with defaults on files (it rewrites quotes/semicolons).
- UI is RTL (`<html lang="fa" dir="rtl">`). Use logical classes (`ms-/me-/ps-/pe-/start-/end-`), not `left/right`. Keep numeric inputs `dir="ltr"`. The Switch forces `dir="ltr"`; the Dialog close button is at the top-left.
- shadcn here is Base UI: triggers use the `render` prop (e.g. `<DialogTrigger render={<Button />}>`), not `asChild`; `Select` takes `items` for label lookup. Dialog/AlertDialog content scrolls with the whole viewport (wrapper `fixed inset-0 overflow-y-auto`), never inside the dialog — don't add `max-h/overflow` to dialog contents.
- Persistence: Dexie db `gamenet-timer-manager` (`src/lib/db.ts`; tables `rateGroups`, `deviceCategories`, `devices`, `extraCategories`, `extraItems`, `customers`, `sessions`, `history`; ordered lists carry an indexed `order`). Components read via `useLiveQuery`; writes go through the helpers in db.ts. **Catalog rows are soft-deleted** (`deletedAt`, see `syncTable` in db.ts): saving Settings never removes rows, it hides them from `readSettings`; creating an entry with the same name (devices/items: same name + category) restores the old row and its id, so history/stats links stay stable. Only history rows are hard-deleted (by the user). On a schema change add a new `version(n)` with `.upgrade()` (never edit an existing one). localStorage keys (simple per-viewer settings, edited in Settings > عمومی): `gamenet-theme`, `gamenet-accent`, `gamenet-title` (app title), `gamenet-icon` (app icon: default / any Lucide icon by kebab-case name via `lucide-react/dynamic` (lazy chunks) / custom PNG data URL; see `src/lib/app-icon.ts`, `AppIcon`, `IconPicker`), `gamenet-rounding` (`{step,mode}`, Settings > عمومی), `gamenet-view` (`detailed`|`compact` session list, default compact; toggle on the main page; compact = 3 small cards per row via `SessionCard compact`), `gamenet-grouping` (default on; Settings > عمومی; when on and >1 device type has devices, the main page shows per-type sections plus a «همه / type» filter row; a chosen type shows alone; while searching it is listed first and the other types follow at 50% opacity). A toolbar search box filters running sessions by any field (`sessionSearchFields` in store.ts).
- Ending a session (اتمام) shows an editable «مبلغ نهایی» (+ «رند کردن» button using the `gamenet-rounding` setting: step + round/floor/ceil, default nearest 1000); `HistoryEntry.total` is that final income (what stats sum), `calculatedTotal` is set only when it was edited. It writes a `HistoryEntry` snapshot (`buildHistoryEntry`) and deletes the session in one transaction. History UI: `HistoryDialog` (shared presets + Jalali range + customer & device-category filters above two tabs: «تاریخچه» grouped by day, 7 days/page; «آمار» = `StatsPanel` KPIs + charts). Stats math is pure in `src/lib/stats.ts`; charts use the shadcn `chart` component (Recharts) with hued `--chart-1..5` vars in `index.css`, each chart wrapped in `dir="ltr"`. Dates/clock use Persian digits via `src/lib/jalali.ts` (Intl-based, no date lib); money stays English digits.
- **Search**: every search box uses the shared engine in `src/lib/search.ts` (`rank` for small lists that change each render, `buildIndex`/`searchIndex` memoized for big ones). It normalizes digits/letters/ZWNJ/punctuation, matches each query word against any field (order independent, weighted fields), tolerates small typos, ranks by matched words then score, and keeps items matching at least half the words. Comboboxes use `useComboboxSearch` (`src/lib/use-combobox-search.ts`: `filter={null}` + `filteredItems`) — never Base UI's default substring filter. A new searchable list only has to provide a `getFields` function.
- Timestamps drive timers (`segments[].from/to`), so running sessions survive reloads; cards re-render once per second only while running.
- TypeScript 6: don't add `baseUrl` (deprecated); the `@/*` alias is configured via `paths` and `vite.config.ts` (`import.meta.dirname`).
