# Gamenet Time Manager (نرم افزار مدیریت زمان گیم نت)

Single-page Persian (RTL, Vazirmatn) game-net session/cost tracker. React + Vite + TypeScript + Tailwind v4 + shadcn/ui (Base UI based "base-nova" style), wrapped as a Tauri v2 desktop app. Data (price types, extra items, sessions, history) lives in IndexedDB via Dexie; viewer/device preferences and UI flags live in `localStorage`.

## Released app: no breaking changes
The app is released (GitHub releases + Pages) and people run it with real data. Every change must keep existing installs, data and backups working; check each change for breaking effects and migrate gracefully instead of assuming a fresh database.
- **Dexie migrations** (`src/lib/db.ts`): never edit, reorder or remove an existing `version(n)`; add `version(n+1)` with only the changed `.stores()` and an `.upgrade(tx => …)` that converts existing rows (backfill new required fields, rename/move data, rebuild derived values). Upgrades must not throw on odd or partial old rows (a failing upgrade aborts opening the db and the app shows nothing), must not lose data (never drop a table or field that still holds data without moving it first), and must work when jumping several versions at once (a user can skip releases). Prefer new fields as optional with a default applied when reading.
- **Old shapes keep working**: code that reads rows, history snapshots, backups or localStorage prefs must tolerate fields missing from older versions (merge with defaults, like the rounding setting). History snapshots are never rewritten, so old entries stay in their old shape forever.
- **Backups**: `parseBackup`/`importBackup` must keep accepting backups made by every earlier release. Imported rows bypass Dexie's `.upgrade()`, so normalize them to the current shape on import (same conversion as the migration). Bump the backup `version` only together with a converter for the older ones.
- **Stable identifiers**: don't rename the Dexie db names (`gamenet-timer-manager`, `gamenet-security`), table names, localStorage namespace prefix (`gamenet-time-manager:`), the Tauri `identifier` (`com.gamenet.timermanager`, it locates the desktop app's data), the Pages origin/base path, or the release asset name `gamenet-time-manager_<ver>_x64-setup.exe` and `releases/download/` URLs (older desktop builds use them to update). If one must change, migrate the old data/value on first run.
- Behavior changes users will notice go into `NOTICE_UPDATES` (bump `NOTICE_VERSION`).

## Commands (pnpm only)
- `pnpm dev` — Vite on `0.0.0.0:3000` (strictPort; Tauri `devUrl` points at `localhost:3000`).
- `pnpm build` — `tsc -b && vite build` (strict, `noUnusedLocals`); run after every change.
- `pnpm tauri dev` — desktop window. `pnpm tauri build --no-bundle` — portable exe in `src-tauri/target/release/` (named after the Tauri `productName`) (no installer; window starts maximized).
- Add shadcn components with `pnpm dlx shadcn@latest add <name> -y`.

## Product model
- **Rates** (نرخ‌ها): named rate groups, each with several per-hour prices + a default (`RateGroup`/`Price`). **Devices**: categories (default پی‌سی، پلی‌استیشن، بیلیارد، پینگ‌پنگ) → devices created in bulk (prefix + count + start number); each device links to ≥1 rate groups and offers all their prices (grouped in selects). A **session** runs on one free device: Add-session picks category → free device → price (default = first group's default) → optional **customer**. The card's price select ends with «تغییر دستگاه…» (`switchDevice`: closes the segment, opens one on the new device/price; paused sessions apply it on resume). Ending (اتمام) shows a cost breakdown dialog and, once confirmed, writes history and **removes** the session. There is no free-text session name anymore.
- Settings dialog is draft-based (ذخیره/انصراف, close = cancel, discard-confirm when dirty, save disabled while a name is empty / a price is 0 / a device has no rate). Tabs: عمومی (dark mode, accent, autostart), نرخ‌ها (`RateGroupsEditor`), دستگاه‌ها (`DevicesEditor`), بوفه (`ExtraItemsEditor`: extra categories + items; the picker shows category filter chips only when >1 category). داده‌ها (`DataTab`, acts immediately, not part of the draft): export a JSON backup of every table + localStorage prefs under `gamenet-time-manager:` (`exportBackup`), import it replacing everything (`parseBackup`/`importBackup`, confirm, then reload), clear history only, or factory reset (`resetAllData` = `db.delete()` + prefs, type «حذف» to confirm, then reload). Customers are NOT in Settings: a separate `CustomersDialog` (top-bar Users button; search + 8/page, edit/delete save immediately, soft delete via `deleteCustomer`; `NewCustomerDialog` creates/edits, also inline from the session flow). `saveSettings` ignores customers. Deleting a price/device/customer used by a running session is blocked (`usageOf`); categories/rate groups must be empty/unused first.
- Cost: a session is a list of **segments** (one continuous run on one device at one price; each carries `typeId` + mirrored price name/value and `deviceId/deviceName/categoryName`). Saving Settings rewrites these mirrors for ALL live sessions via `applyPrices`/`applyDevices`/`applyExtraItems` (in one transaction, `saveSettings`); history snapshots are never touched. Changing the price while running closes the segment and opens a new one. Time cost is billed per whole second, rounded up (`segmentCost`). Backdating time («زمان گذشته», `addBackdatedTime`) adds minutes *before* a session's recorded history instead of being a separate entity: it compares the picked device against the session's oldest segment's device — same device just pushes that segment's `from` back; a different device prepends a new segment ending exactly where the old oldest segment began, billed at that device's default price (editable afterwards like any other segment). Extra items are `price × qty` (catalog items keep `catalogId`; the «موارد دیگر» item has a raw price and optional description). Total = Σ segments + extra items.
- **Naming rule: «بوفه»/"buffet" is a UI-only term.** In source code (identifiers, file names, component names, ids, comments, types, DB) always say *extra cost* / *extra item* (`extraItems`, `ExtraItemPicker`, `SaveExtraItemDialog`, `save-extra-item-dialog.tsx`), never `buffet`. Persian UI strings may say «بوفه».
- Wording: the extra-items catalog (`extraItems`/`extraCategories`, Settings tab, picker, stats) is called **«بوفه»** (never «موارد اضافه»/«هزینه اضافه»); extra *time* stays «زمان اضافه». Wording: a `Session` is called **«تایم»** in the UI (never «نشست», which means "sitting"): «افزودن تایم», «تایم‌های پایان‌یافته», «پایان تایم». Wording: a `DeviceCategory` is called **«نوع دستگاه»** in the UI (never «دسته‌بندی»; that word is only for extra-cost categories). New types/categories start with an empty name and a placeholder (e.g. «مثلاً پلی‌استیشن»); an empty name keeps Settings unsaveable. Devices are added with two buttons («افزودن دستگاه» single, «افزودن چند دستگاه» bulk), edited via the pencil dialog, and «نرخ همه» sets the rate groups of every device of a type.
- **نسیه (debt)**: ending a session with a customer offers «پرداخت شد» / «نسیه» in `SessionSummaryDialog`; نسیه sets `HistoryEntry.onAccount` (stats still sum `total` as income; the history dialog has a «نحوه‌ی پرداخت» filter to switch between paid / نسیه / both). A customer's balance = Σ on-account `total` − Σ `payments` rows (Dexie v3 table `payments`, `addPayment`); computed by `readDebts` (all customers, deferred) / `readCustomerLedger`. `CustomersDialog` shows a debt column, «بدهکاران» filter and `CustomerDebtsDialog` (ledger + «ثبت پرداخت», amount ≤ balance); a customer with unpaid debt cannot be deleted. Deleting a history entry removes its debt.
- **Time limit** (محدودیت زمانی): optional `Session.limitMs` = total running-time budget; countdown = `limitMs − elapsedMs` (pause freezes it, extra times don't count). The edit dialog (`LimitDialog`) works on the *remaining* minutes (`setLimit` = elapsed + minutes; `extendLimit` extends from now when already exceeded; `clearLimit` behind a confirm). `LimitAlarmDialog` (mounted once in `App.tsx`) shows one non-dismissable queued dialog for running sessions past their limit (+5 دقیقه / ویرایش / توقف) and beeps via `src/lib/alarm.ts` immediately and every 10 s. It is on top via the `raised` prop of `DialogContent`/`AlertDialogContent`/`useDiscardGuard` (z-100); anything opened from the alarm must pass `raised`. Each newly expired session also calls the operator back (`src/lib/attention.ts`, always on): desktop unminimizes/focuses the window + `requestUserAttention` (window permissions in `capabilities/default.json`); web can't focus itself, so when the page has no focus it shows a `Notification` (permission is requested when a limit is set: `LimitDialog` save / add-session with a limit) whose click focuses the window (`public/notification-click.js`, imported into the SW via `workbox.importScripts`, handles SW-shown notifications).
- **App lock** (قفل برنامه): optional 4–8 digit PIN set in Settings > امنیت (`SecuritySettings`, acts immediately). `src/lib/security.ts` keeps a PBKDF2-SHA-256 salted hash + auto-lock minutes + wrong-attempt counter/`lockedUntil` (30s/1m/5m/15m after every 3 wrong) + `forgotAt` in its own IndexedDB db `gamenet-security` (never in backups; `resetAllData` clears it; `persist()` requested). While locked (page load, lock button, idle) `App` renders ONLY `LockScreen` (+ the DOM-less `LockedLimitAlarm`); `Main` is not mounted at all, so no app HTML exists until the PIN is verified; `useIdleLock` locks after idle; top-bar Lock button only when a PIN exists. «فراموشی رمز» starts a 24h persisted countdown (PIN entry disabled until «لغو»); after 24h «حذف رمز» removes the PIN only. Client-side deterrent, not tamper-proof. The time-limit beep keeps sounding while locked via `LockedLimitAlarm`.
- **Notice** (پیش از شروع بخوانید): `NoticeDialog` (`src/lib/notice.ts`) is a blocking accept-checkbox dialog shown before onboarding to everyone until `NOTICE_VERSION` is accepted (stored in localStorage with the shared `gamenet-time-manager:` prefix). To announce an update: bump `NOTICE_VERSION` and add bullets to `NOTICE_UPDATES[version]` (shown as «تغییرات این نسخه» to users who accepted an older version); edit `NOTICE_LIMITS` for the limits list.
- Display: English digits with thousands separators, label «تومان» placed **outside** inputs.

- **PWA / releases**: `vite-plugin-pwa` in `vite.config.ts` (manifest, `registerType: 'prompt'`, icons `public/pwa-192.png`/`pwa-512.png`; disabled for Tauri builds via `TAURI_ENV_PLATFORM`; `base` from `BASE_PATH`). **`package.json` `version` is the single version source** (`__APP_VERSION__`, `tauri.conf.json` `"version": "../package.json"`); the release workflow sets it from the pushed `v*` tag. `.github/workflows/deploy.yml`: tag → one Windows `build` job builds the web PWA (Pages artifact only, not attached to the release; `dist` moved to `web-dist` before the Tauri build overwrites it; the web build step uses `shell: pwsh` because Git Bash rewrites `BASE_PATH=/repo/` into `C:/Program Files/Git/repo/`) and then the Windows NSIS installer (`gamenet-time-manager_<ver>_x64-setup.exe`) → GitHub release (tags with `-` are pre-releases) → deploy Pages (Settings > Pages > Source = GitHub Actions). Tag runs can't read other tags' caches, so `.github/workflows/cache.yml` warms the pnpm + Rust caches on main (Windows only) (lockfile pushes, weekly, manual; rust-cache `shared-key: desktop`); deploy.yml only restores them (`save-if: false`). Both share the concurrency group `release`: a release cancels any running release/warm-up; a warm-up never cancels a release (it waits). Data is per-origin: web and desktop don't share it (use the JSON backup).
- **Install / update**: `src/lib/platform.ts` (`isTauri`, `APP_VERSION`, `REPO`), `release.ts` (GitHub releases API, `compareVersions`), `install.ts` + `InstallDialog` (web only, not when standalone/Tauri: PWA `beforeinstallprompt` or the exe from releases; opens once; top-bar Download button), `update.ts` + `UpdateDialog`. Web update = service worker `needRefresh` (`registerPwa()` in `main.tsx`); desktop update = newer GitHub release → Rust commands `download_installer` (only `releases/download/` URLs, emits `update-progress`) and `run_installer` (detached process, NSIS flags `/P /UPDATE /R`: progress only, no reinstall/uninstall page, relaunch) → window `destroy()`. «رد کردن این نسخه» is stored in localStorage with the shared prefix. Both checks (release fetch, SW `reg.update()`) run at startup and every 10 min (`CHECK_EVERY`).
- **Single instance**: desktop = `tauri-plugin-single-instance` (first plugin in `lib.rs`; a second launch exits and unminimizes/focuses the `main` window). Web = `src/lib/single-instance.ts` (Web Lock `gamenet-instance`, started in `main.tsx`): only the lock holder renders the app; other windows render only `InstanceScreen` («استفاده در این پنجره» = BroadcastChannel takeover). The PWA manifest has `launch_handler: focus-existing`.
- **Footer**: `App.tsx` shows `v{APP_VERSION}` and an author link to the GitHub repo.

## Guided tours (driver.js) — keep them in sync
Every guide flag in localStorage is `<prefix>tour:<name>` (`tourKey`/`tourSeen`/`markTourSeen` in `tour.ts`, e.g. `tour:skip`); never add one outside that namespace. Step-by-step guides are offered after onboarding (skip flag `tour:skip` in localStorage, never in backups) and replayed with **F1** (F1 only). `src/lib/tour.ts` is only the engine (`registerTour`, `startTour`, `startTourById`, `startGuide`, `setTourFollowUp`/`takeTourFollowUp`, `tourSel`, `tourLatest`); **each component owns its steps** next to its markup, targeting `data-tour="…"` attributes, and registers them: `addSessionTour` (`add-session-dialog.tsx`, priority 10: search → picker → customer (forced on first run) → limits → prepay → start), `sessionCardSteps()` (`session-card.tsx`: card, device, customer, timer, cost, price, pause, limit, backdate, extra; plus `pausedTour` there: ادامه/اتمام, shown once on the first pause via `offerPausedTour`, flag `tour:paused-seen`, not tied to F1), `summaryTour` (`session-summary-dialog.tsx`: top-to-bottom through times, extra cost lines, prepay, totals, final amount, customer, settlement, payment type, buttons; steps whose target is missing are skipped; once by itself, flag `tour:summary-seen`), `backdateTour` (`backdate-time-dialog.tsx`: device, minutes, add; once by itself, flag `tour:backdate-seen`), `limitAlarmTour` (`limit-alarm-dialog.tsx`: what happened, quick extend (amounts from Settings > عمومی), edit, stop; once by itself, flag `tour:limit-alarm-seen`), `limitTour` (`limit-dialog.tsx`: time, cost, remove, save; limits start at the moment of saving; once by itself, flag `tour:limit-seen`), `extraPickerTour` + `extraOfferTour` (`extra-item-picker.tsx`: search, catalog choices, «سایر هزینه‌ها», counter vs price/description/count; then the «add to buffet or keep as text» question; both open once by themselves, flags `tour:extra-picker-seen` / `tour:extra-offer-seen`), `mainTour` + `sessionsTour` (`App.tsx`: the card steps, then type filter, view toggles, shift summary, reserve, add time, history, customers, theme, settings). Flow: onboarding → prompt → `mainTour` → add-session guide → creating the session starts `sessionsTour` (`setTourFollowUp` flag, consumed in `App.addSession`).
- Every dialog that has a guide shows a small «?» (`TourHelpButton`, `tour-help-button.tsx`, `tour="<registered id>"`) beside its title that starts the same guide as F1 (currently add-session, extra cost picker, its «add to buffet?» question, limit dialog, limit alarm, past time, final cost/summary). Give a new guided dialog one too.
- **When a change touches UI that a guide points at** (renaming/moving/removing a button, field, dialog step or toolbar control that carries a `data-tour`; changing what a step explains, e.g. limits, prepay, reserve, rates, shift summary; adding a feature the guide should mention), update that component's tour steps and `data-tour` attributes in the same change, and **tell the user** which steps were affected. For a **new** feature or screen, ask the user whether it needs a guide (or a new step) instead of silently skipping it. Never leave a step whose `data-tour` target no longer exists (the guide would skip or highlight the wrong thing).
- Keep step texts Persian, matching the UI wording rules above. Steps that only explain use `disableActiveInteraction: true`. Dynamic steps use `waitForElement`/`skipMissingElement`; mark steps whose target is a dialog that may close with `data: { keepAlive: true }`.
- After editing a tour, replay it (F1) in the browser (the playwright-core + Edge scripts used before are a fast way) and run `pnpm build`.

## Conventions & gotchas
- **File names are always kebab-case** (`session-card.tsx`, `use-now.ts`), for new files and renames (use `git mv`; on Windows case-only renames need a temp name). Exports and component names stay PascalCase/camelCase; imports use the `@/components/session-card` form.
- Style: single quotes, no semicolons, ~100 col, trailing commas. Do **not** run prettier with defaults on files (it rewrites quotes/semicolons).
- UI is RTL (`<html lang="fa" dir="rtl">`). Use logical classes (`ms-/me-/ps-/pe-/start-/end-`), not `left/right`. Keep numeric inputs `dir="ltr"`. The Switch forces `dir="ltr"`; the Dialog close button is at the top-left.
- **Always use shadcn components; never raw elements.** For anything interactive or structural use `src/components/ui/*` (`Button`, `Input` incl. `type=file`, `Label`, `Checkbox`, `Switch`, `Slider`, `Select`, `RadioGroup`, `Table*`, `Tabs`, `Badge`…), not raw `<button>/<input>/<label>/<select>/<textarea>/<table>/<input type=range>`. If a component is missing, add it with `pnpm dlx shadcn@latest add <name> -y` before hand-rolling. Icon/clickable custom looks use `Button variant="ghost"` with class overrides (add `max-md:h-auto` etc. to beat its mobile sizes). Size things in `rem` (not px) so the interface scale setting keeps them proportional.
- **Never use native browser dialogs** (`window.alert`, `window.confirm`, `window.prompt`). Use shadcn `AlertDialog`/`Dialog` components for all confirmations, warnings and prompts.
- shadcn here is Base UI: triggers use the `render` prop (e.g. `<DialogTrigger render={<Button />}>`), not `asChild`; `Select` takes `items` for label lookup. Dialog/AlertDialog content scrolls with the whole viewport (wrapper `fixed inset-0 overflow-y-auto`), never inside the dialog — don't add `max-h/overflow` to dialog contents.
- Persistence: Dexie db `gamenet-timer-manager` (`src/lib/db.ts`; tables `rateGroups`, `deviceCategories`, `devices`, `extraCategories`, `extraItems`, `customers`, `sessions`, `history`; ordered lists carry an indexed `order`). Components read via `useLiveQuery`; writes go through the helpers in db.ts. **Catalog rows are soft-deleted** (`deletedAt`, see `syncTable` in db.ts): saving Settings never removes rows, it hides them from `readSettings`; creating an entry with the same name (devices/items: same name + category) restores the old row and its id, so history/stats links stay stable. Only history rows are hard-deleted (by the user). On a schema change add a new `version(n)` with `.upgrade()` (never edit an existing one; see «Released app» above). localStorage keys must always be built through `prefKey(...)` from `src/lib/store.ts` (prefix: `gamenet-time-manager:`) for every new usage. Current pref names include theme/accent/title/icon/view/grouping/rounding/ui-scale/font-scale/quick-extend/shift-summary-visible/notice/install-seen/skipped-update/autostart-init/tour-skip. A toolbar search box filters running sessions by any field (`sessionSearchFields` in store.ts).
- Ending a session (اتمام) shows an editable «مبلغ نهایی» (+ «رند کردن» button using the rounding setting: step + round/floor/ceil, default nearest 1000); `HistoryEntry.total` is that final income (what stats sum), `calculatedTotal` is set only when it was edited. It writes a `HistoryEntry` snapshot (`buildHistoryEntry`) and deletes the session in one transaction. History UI: `HistoryDialog` (shared presets + Jalali range + customer & device-category filters above two tabs: «تاریخچه» grouped by day, 7 days/page; «آمار» = `StatsPanel` KPIs + charts). Stats math is pure in `src/lib/stats.ts`; charts use the shadcn `chart` component (Recharts) with hued `--chart-1..5` vars in `index.css`, each chart wrapped in `dir="ltr"`. Dates/clock use Persian digits via `src/lib/jalali.ts` (Intl-based, no date lib); money stays English digits.
- **Downloads**: every exported file goes through `saveFile` (`src/lib/download.ts`): `<a download>` on the web; in Tauri (where webview downloads do nothing) the Rust `save_file` command (raw body + URI-encoded `x-file-name` header) shows a native Save dialog via `tauri-plugin-dialog` and writes it.
- **Report export** (`src/lib/report-export.ts`, «خروجی گزارش» menu in `HistoryDialog`): exports the currently filtered history as CSV (sessions only, UTF-8 BOM), XLSX (dependency-free writer: stored zip + SpreadsheetML, RTL sheets: تایم‌ها / خلاصه روزانه / مشتریان / بوفه; money as numbers) or PDF (print-ready HTML in a hidden iframe → user picks «Save as PDF» in the print dialog, so Persian shaping stays correct). Dates are Jalali with English digits.
- **Search**: every search box uses the shared engine in `src/lib/search.ts` (`rank` for small lists that change each render, `buildIndex`/`searchIndex` memoized for big ones). It normalizes digits/letters/ZWNJ/punctuation, matches each query word against any field (order independent, weighted fields), tolerates small typos, ranks by matched words then score, and keeps items matching at least half the words. Comboboxes use `useComboboxSearch` (`src/lib/use-combobox-search.ts`: `filter={null}` + `filteredItems`) — never Base UI's default substring filter. A new searchable list only has to provide a `getFields` function.
- Timestamps drive timers (`segments[].from/to`), so running sessions survive reloads; cards re-render once per second only while running.
- TypeScript 6: don't add `baseUrl` (deprecated); the `@/*` alias is configured via `paths` and `vite.config.ts` (`import.meta.dirname`).
